# D · Evaluation & Migration Roadmap

状态：2026-10-14 按个人规模的 Product Convergence 任务修订。当前采用 14 篇真实内容、同 Renderer 的 Baseline/探索页面、自动完整性检查、独立模型辅助评论与个人实读；不招募读者、不做问卷或统计显著性检验、不引入 Eval 平台。下方 24 项表保留为历史候选池；本轮实际 corpus 与结果见 [本轮交付](../convergence-2026-10-13/DELIVERY.md)。

## 1. 必须分开的三个质量问题

| 层 | 要回答的问题 | 主要方法 | 不能替代它的指标 |
|---|---|---|---|
| Integrity Evaluation | 输入、定稿、来源、数字/限定词、图像和双语映射有没有损失、错配或编造？ | 精确正文/引用/资产身份检查；有原来源时人工核验事实与翻译 | HTML 存在、条数、Schema PASS |
| Editorial Decision Evaluation | 干预是否解决真正困难？位置、关系和辅助事实是否成立？该不干预时是否不干预？ | 人工标注可接受选择与反例；以源码为依据的 rubric；校准后的 Judge 辅助 | 使用多少组件、选择了 L02/L03、调用成功 |
| Reading Experience Evaluation | 页面相对公平 Baseline，是否提高理解、查找、连续阅读舒适和编辑品质？ | 同内容实页、Before/After、桌面/手机截图、独立模型评论和个人设计审查 | 零溢出、字体一致、组件精致、Judge 喜欢更丰富的页面 |

第一层是底线，后两层是收益。不能平均成一个总分，让漂亮的页面抵消正文丢失。

### 两级完整性证据

- **输入到输出的完整性**：可以在现有 final/crops 上马上核查，证明 Engine 没有丢字、错配或错误执行。
- **输入相对原来源的完整性**：需要原报/原图/可信结构化原文与译文审校。仓库缺 PDF 时，源完整性只能标 unresolved，不能由渲染精确一致替代。

不要求本阶段重新 OCR/重译整期。先让 Engine 对已经拥有的内容忠实负责；原报缺失和图表恢复债務在 Adapter 范围内单独列出。

## 3. 成熟 Eval 方法比较与选择

资料核查日期：2026-10-13。只核查官方功能和方法，没有安装、注册、运行这些平台；不作未经测量的价格/性能排名。

| 方法/工具 | 官方能力 | 对当前规模的收益 | 成本与边界 | 建议 |
|---|---|---|---|---|
| [Promptfoo](https://www.promptfoo.dev/docs/intro/) | 本地开源 CLI、模型/提示矩阵、code/LLM 断言、缓存、可配置 Provider | 正适合几十篇离线比较、一两个 prompt/model 与回归；[Python provider](https://www.promptfoo.dev/docs/providers/python/) 可调用现有逻辑 | Node 开发依赖；仍需自己定义源证据、页面生成与读者任务；不会自动知道排版好坏 | 当前唯一推荐的新增 Eval 工具；先锁版本，在 dev 环境接入 |
| [Braintrust](https://www.braintrust.dev/docs/evaluate) | dataset/task/scorer、实验快照、在线评分、CI、人工/自定义/LLM 评估 | 团队共享与跨运行分析成熟；值得借 dataset/task/scorer 分离思想 | 需要平台接入和数据管理；当前无持续在线请求流，收益有限 | DEFER；团队评审/在线跟踪成为实际需求再评估 |
| [LangSmith](https://docs.langchain.com/langsmith/evaluation) | 离线/在线 eval、数据集、code/human/LLM/pairwise、重复/并发/缓存配置 | 多步骤 tracing 与产品请求调试有用 | 平台配置与额外运行记录；静态一期工具没有足够 tracing 需求 | DEFER；不因此引入 LangChain |
| 本地文件 corpus + Python checks + 浏览器 + 人工任务 | 不依赖平台即可保存完整输入/产物/评分 | 当前马上可做、同现有代码贴合 | 若继续自造报告 runner，容易再分裂语义 | 基础层；只写必要领域 checks，不自建通用 Eval Framework |

当前选择：**本地 corpus、现有 Python 的完整性检查、同 Renderer 的实页与个人设计审查。** Promptfoo 等工具仅保留为未来有真实重复比较需求时的选项；本轮不安装或接入平台，也不开发通用 Eval Framework。

Promptfoo 本地运行不等于模型调用离线：数据仍发送到配置的 Provider。[官方缓存说明](https://www.promptfoo.dev/docs/configuration/caching/) 指出重复索引有自己的缓存空间；测随机波动时需 fresh sampling，不能重复读取缓存就宣称稳定。

总计 24 篇/项，不把同一文章的多版本算作不同独立样本。

### 数据集结构

每个 case 记录：case_id、ArticlePackage 路径/hash、来源核验状态、文章类型/长度、已知问题、exposure（人工打磨/旧 Planner 已见/未知）、阅读任务、参考答案及证据、可接受干预集合、禁止干预、assets 与语言要求、评审者/日期/rubric_version。

Gold 标注是**可接受选择集合**，不是唯一 JSON 答案。例如收益率稿允许真正有帮助的比较，也允许保留正文加有限强调；必须拒绝把不同预测口径拼成同一对照。短稿不干预也必须完整保留署名和导语。

### 数据划分与污染控制

- 已手工打磨的四篇长稿用于开发与回归；它们不能再被称为盲测。
- 当前固定 14 项，不作 12+12 的开发/保留分区。逐篇记录是否反复手工设计、是否进入历史管线；关注具体退步与遗漏，不用总体胜率遮盖问题。
- 之后可自然补入下一期文章检查泛化；第二期和外部读者不是本轮完成条件。
- 评价要点由通读原文后预先记录，再看 Plan/页面。独立 AI Judge 仅辅助指出问题，最后由实际阅读体验判断。

### 必需的坏例与边界变体

在原 snapshot 之外保存独立 variant，注明它是故意损坏样本：

1. 保持前 24 字、改后文；应被全文检查检出。
2. CN/EN 段数不同但各自完整；必须保留双方，不能按 min/单侧截断。
3. 插入首段、重排两段、修改被引用片段、重复同一句；验证持久 ID、范围与 stale 判定。
4. `&`、`<`、引号、emoji 与重复数字；强调必须命中原字符范围，转义不可移动目标。
5. 缺失 block_id/asset_id、未知操作/版本、冲突范围；不能 silent skipped。
6. 虚构 quote/边注事实、增补年份、错单位、截掉“可能/据称/不”；来源/语气检查需发现。
7. 资产属于另一篇、图注/credit 未确认、图表缺轴/时间区间；有文件不等于可发布。
8. Plan preserve 与零操作无 Plan 对照；正文与 metadata 应完全等价。
9. Provider 超时/响应坏 JSON、恢复同一 run、内容尾部变化；失败不伪装为 preserve，不污染缓存或覆盖成品。
10. 英文模式下的 comparison 标签与新增解释；不能只隐藏中文后剩下无身份的数字。

这些变体用来检验完整性和明确拒绝行为；不要用它们替代真实文章的阅读评测。

## 5. 三层具体评测

### Integrity：不被均分稀释的发布门槛

机械检查覆盖双方所有正文块/metadata 的精确字符串、出现次数、顺序；受限 heading/list/table 类型；Selector 的范围与 exact；每个 accepted 操作的执行回执；asset hash/来源/图注关系；状态和出版 selection。

原来源语义核查覆盖：译文事实、数字与单位换算、否定/限定、说话者与引文、图表轴/时间区间、外部新增解释。不能只比较数字字符串集合：`12.7M` 与 `1270万` 可以同义，`5.1%` 的单位/预测年份仍可能错误。

发布门槛：无新增已确认的正文损失、错配、虚构事实或误归属。已知输入问题独立标 unresolved/blocked，不能从完整性分母中消失；发布范围允许变化，但必须显式且可复核。

### Editorial Decision：评估选择，而非组件分类

每个候选 reader_need 按四项 0–2 评分（分项报告，不作为完整性的豁免）：

| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| Need | 装饰/无困难或解释错问题 | 有可能帮助但困难不明确 | 对应可具体指出的理解/查找困难 |
| Evidence | 无来源、错误关系/语气 | 引用有但关键关联未确认 | 事实、归属、限定与同维度关系完整 |
| Intervention | 打断、重复或制造假重点 | 有收益但代价可降低 | 方式与位置合适，收益清楚超过成本 |
| Restraint | 为填充而干预/漏掉必要保护 | 大体克制但仍有多余/遗漏 | 正确拒绝无收益方案，必要关系不遗漏 |

严重 evidence 错误直接 failure，不能靠其他维度补分。记录“有害干预率”“正确 preserve”“必要机会漏判”和具体原因，不以 pattern 使用率做 KPI。

Judge 输入包括原内容、来源摘录/状态、Plan、实际执行回执和任务；不能只看 Plan 的说理文字。检查建议是否已真实渲染，防止奖励未执行的功能。

### Reading Experience：公平的 Baseline 与读者任务

准备同 content revision、同来源修复/资产集合、同 WSJ design profile 的两页：无编辑操作 Baseline，与待评 Plan。资产位置可由 Plan 改变；不能让 Baseline 少图、少英文、保留错位而增强页修好。

候选任务：

- E1-010：找出三段预测期限与 10 月/7 月收益率；解释“上调”结论及反方观点。测正确率、查找时间与对象/单位混淆。
- E2-002：区分民用监控规模、具体处置规模与不同战区案例；定位调查方法/机构归属。测是否被异口径数字总览误导。
- E1-005：恢复事件先后与核心约束；连续读完机场场景，观察插入模块是否打断理解。
- E3-004：说明开篇场景如何支持论点，区分记者描述与人物观点；观察章节和强调是否制造过度确定。
- 数据图：找到轴、单位、时间范围和某数值的来源；测试手机横滑后能否理解图与正文关系。
- E1-014/E1-015：快速获得事实、地区和来源；验证“没有增强”不会让任务变差。

用本人设计审查和独立模型评论比较实际桌面/390px页面，记录具体位置、win/tie/loss 与不同意见。叙事是否更连贯、限定是否被保留、手机是否舒适，都必须指向实页。不要把个人偏好包装为总体读者的因果结论。

舒适度与编辑品质按 1–5 描述锚点评分：1=显著阻断/混乱，3=与清晰 Baseline 相当，5=结构帮助理解且连续阅读更轻松；必须附具体位置与行为。整体 identity 看整期跨文章样本，不能只看单篇 hero。

本轮接受条件：

- 无确认的完整性回归；所有接受操作有实际执行回执。
- Preserve 不丢 metadata/正文/资产，失败不伪装成 preserve。
- 逐篇说明真正解决的阅读问题、代价与仍不满意的位置；允许平局和撤回干预。
- 三种处理在真实页面可比较；不以组件数量、测试通过或零溢出裁定设计。
- 不设招募人数、胜率、查找时间百分比或统计显著性门槛。最终满意度由实际阅读和 Jerry 的判断决定。

## 6. LLM Judge 的使用边界

[Zheng 等，MT-Bench / Chatbot Arena，NeurIPS 2023](https://arxiv.org/abs/2306.05685) 研究了位置、冗长、自偏好等偏差及有限推理能力。论文中的对话偏好一致性不能直接推到中文新闻阅读或版式品质。

采用方法：先用人审样本校准 Judge；固定 rubric；A/B 顺序随机且交换顺序复评，冲突判 tie/送人工；隐藏作者/模型/“enhanced”名字；允许“不确定”；同一模型作者的自评不能作为唯一裁判。将 Judge 与人工一致性及分歧单独报告。

文本 Judge 可以评估证据、关系和重复；截图 Judge 可以辅助发现明显层级/拥挤问题。它们不能测量真人理解、查找时间、连续阅读舒适。更多 Judge 投票也不能自动形成真实性。

## 7. 可重放的长期评测流程

1. 固定 corpus、参考证据、任务、rubric 与 exposure；新反例增补为新 Benchmark 版本。
2. `import/render` 先生成共同 Baseline；跑完整性。失败样本继续记录 failure，不通过缩小分母“修复指标”。
3. 比较候选 prompt/model 的 Plan；保留 raw response、费用/延迟、参数与每次新采样标识。
4. 同一 Renderer 执行 Plan，核对操作回执，保存双方页面/截图与 hash。
5. code checks + 校准 Judge 作预筛，人审真实页面与少量读者任务作最终裁决。
6. 输出逐例 Integrity、Decision、Reading、运行成本与版本；不只保存 PASS 汇总。
7. 仅 prompt/模型变化重跑 planning+下游；仅 CSS 变化重跑 render+reading；rubric 变化重评已存页面；正常完整性回归每次出版运行。

日常不必每期每篇都找真人测试。每次生成运行 Integrity，审核重大新增事实/图表与明确问题；每次编辑策略/模型/设计重要变更运行固定 Benchmark，并抽样整期 identity。新日期轮换进入未见样本池。

## 8. 第一项值得实施的工作

**P0：一个忠实正文投影，共同驱动普通、增强与 Baseline；修复英文尾段和 preserve metadata。**

理由：两个缺陷已经在正式产品中发生。修复直接恢复读者可访问内容与报道来源，不需要换模型、引入平台或改变视觉身份；也为所有后续编辑收益评测建立有效对照。

### 严格范围

- 从当前 `final.json` 形成同一只读内容视图，保留双方完整正文和 metadata；不在 Renderer 临时决定对齐/删 marker。
- 将已有英语合段/marker 修复以显式数据记录放在共同输入投影，保留原快照与诊断，不直接覆盖正文原始数据。
- 普通/增强/空 Plan 共用正文与文章头部；保留 current CSS、类型差异、既有四篇增强效果、栏目/头版与已选资产。
- 不实现新 Planner、不扩 Pattern、不做 OCR/重译、不迁语言、不顺便全合并资产清单。

### 可验收行为

1. E2-010 英文最后两段完整可读；中文保持原有 14 段；不以相同段数伪造一一映射。
2. E1-014 有明确 preserve Plan 时仍保留“佛罗里达州”与 `—Associated Press`；与无 Plan 的同类型页面元数据/正文相同。
3. E1-005/E2-002 的共同底稿在 Baseline/增强页中相同，修复不随是否有编辑计划改变；原始来源快照仍可取得。
4. 双方所有正文块精确保留且顺序正确；刻意损坏后文的样本必须失败。原始 heading/图注分类有显式来源或修复依据。
5. 1440/390 实页、中英切换、收益率比较/摄像头边注/短讯实际可读，既有已选资产保持；没有把未执行操作标为成功。
6. 至少保留针对 EN 尾段丢失与 preserve metadata 的永久行为回归；它们验证消费者实际看到的内容，不测试源码字符串。

这项工作完成前，不声称新 Benchmark 能公正比较编辑收益。修复完成也只证明恢复内容与可比性，阅读提升需继续测。

|---|---|---|---|
| P0 忠实正文与公平对照 | 共用正文/头部，当前正式页修复，行为回归与实页证据 | 上述六项；不需要原 PDF 或模型 | 保留原 dist/plan；对齐债务不伪造解决 |
| P1 内容契约 | ArticlePackage importer、持久 IDs、alignment、source/asset状态；一次 legacy map | 完整原输入保管、同样本往返与跨段插入稳定；结构化直入可用 | 不覆盖 final；转化失败保留问题；原来源缺失仍 unresolved |
| P2 唯一 Plan 执行语义 | 将五份计划及旧组件数据转换成同协议；统一 dispatch；所有 accepted ops 有回执 | preserve 等价、unknown/stale fail、source头部不启发式；旧 0/1-based slots 正确迁移 | 按文章逐项对照；不永久兼容四种方言 |
| P3 每期配置与真实 CLI | edition/资产/策展按期存；去117；顺序 run、完整 hash 缓存与原子产物 | 1篇/多篇任意结构化包、第二期不读旧资产、失败恢复同结果且不覆盖有效页 | 小范围替代 pipeline；不增加编排平台 |
| P4 可替换 Planner | 一个 prompt、可配置 Provider、外部 Plan 输入、理解/选择日志；选定 Adapter 输出同 Content | 保留样本/反例表现，不把 failed 当 preserve；新增事实有依据 | 人工计划仍可用，核心 render 不依赖活模型 |
| P5 日常质量循环 | 小 corpus、固定评价要点、同 Renderer 实页、独立模型辅助与个人实读 | 分别报告三层结果；逐篇说明收益、代价与不确定性 | 未满意可保留忠实 Baseline；不得用组件计数替代阅读判断 |
| P6 历史入口停用 | 已迁能力和样本索引；旧 builders/planners 放历史归档 | 所有受影响调用、有效测试/规范迁完且同一生产路径可运行 | 保留源代码、资产、原始响应和重要截图，不破坏性删除 |

Benchmark 的样本标注从 P0 开始，贯穿 P1–P4；P5 是日常化，而非等到所有迁移做完才首次读页面。每阶段独立可评审、可回退，不一次性更换正文、模型、资产和视觉系统。

P2/P3 之后唯一生产路径是 ArticlePackage + EditorialPlan（可 preserve）→ 同一 Renderer → RenderResult + 阅读页面。外部 Provider、OCR/MT、Cron、Personal Agent 只接这条路径，不各建一条 Builder。

## 10. 本轮验证与仍缺的证据

已完成：一期隔离重建且 hash 相同；正式 DOM/1440/390与中英切换；18图加载；正文/metadata/锚点/操作/缓存/小结构化输入探针；现有测试 16 条通过；官方内容协议与 Eval 文档比较。

未完成且本轮不应伪称完成：源 PDF 全量核验、真实 OvisOCR2/Hy-MT2/Planner 推理、Safari/Firefox、第二个真实日期、独立读者理解/查找测量、Benchmark Gold 标注、新 CLI/协议实现。

这些缺口不会阻断 P0。源完整性与未见日期验收需要取得可信的原始或结构化输入；先完成不依赖它们的内容忠实性修复和局部收敛。

**最终决策：先让同一份内容被忠实、稳定、可比较地编辑，再证明每一种干预给读者带来的收益。现有设计和渲染骨架值得继续使用；新框架、更大的目录和更多 Validator 不能替代这个闭环。**
