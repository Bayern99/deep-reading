# 一份整期交付制品就是产品

**状态：已接受**

面向读者交付的产品是一份便携的整期交付制品：由一期外部工作区编译而来的自包含 HTML 出版物。工作区提供 PDF、印刷证据、已审核双语内容、路由和编辑输入；工具仓库提供可复用指示、规则与代码。

整期交付制品包含期号概览和沉浸式阅读。读者看到的是出版物，不是生产控制台。LQA 与认证报告保存在外部工作区中，与制品并列。

## 决策

**只保留一种产品界面和一种期号工作流程。** 编译器生成一份 HTML 制品。中间文件和报告属于工作材料，不构成其他产品。选定的外部期号根目录是本期内容的唯一来源。

## 考虑过的方案

- **增加面向读者或操作人员的交互式工作台：** 否决。它会形成独立产品界面，并把生产状态暴露给读者。
- **增加使用不同证据与叙事规则的第二条编译流程：** 否决。不同流程可能对权威内容和质量规则产生冲突。
- **把工作区清单、LQA 报告或认证细节嵌入阅读器：** 否决。这些内容对操作人员有用，却会干扰读者；HTML 应保持出版物形态。
- **在可复用工具包中保存有日期的期号数据：** 否决。发布包不应依赖私人或预先准备的期号才能运行。每位使用者提供自己的外部期号工作区。

## 后果

- 权威产品文档只描述外部期号工作流程和唯一的整期交付制品，不再规定第二种阅读应用。
- 用户流程为 `prepare_issue` → 审核文章发现结果和译文 → 最终整理期号清单 → `tracer_pipeline --issue-root` → HTML 与工作区报告。详见 [编译构建](../../render/BUILD.zh-CN.md)。
- `make tracer ISSUE_ROOT=...` 生成阅读制品和 LQA 报告。`make tracer-certify ISSUE_ROOT=...` 还会为本期生成七项神谕报告。
- HTML 不嵌入期号 PDF、译文清单、原始证据或工作报告；这些都保存在外部期号根目录。
- 当源码包能够从新的外部期号根目录运行，且不依赖包内期号材料时，即达到可复用条件。
