# WSJ 深读重设计 · 评审说明（review）

日期：2026-10-13。测试内容：沙特长文 E1-005（24 段正文，final.json 定稿，一字未动）。

## 设计策略

**一句话**：Al Jazeera 的信息架构 + WIRED 的字体雄心，做一套统一的中文深读设计语言，不是拼贴。

- **AJ 负责**：新闻流的组织方式——masthead → 标题头 → 640px 正文栏 → 模块嵌入流；模块的节制（每个模块必须有独立阅读价值）；颜色纪律（橙只做标记、红只做时间线）；右 rail 导航。
- **WIRED 负责**：三字体分工（展示衬线 / 正文衬线 / 元数据无衬线）；标题即 hero；引语作为节奏锚点；发丝线 + 留白的编辑质感。
- **中文重做**：西文规范不直接搬运——标题字重 900（不抄西文 400）、正文 18px/1.9（不抄 16px/1.5）、禁用 text-wrap:pretty、禁用首字下沉。

## 关键决策

1. **字体系统**：Noto Serif SC 900（标题 48px）/ Noto Serif SC 400（正文 18px/1.9）/ Noto Sans SC（元数据）/ mono 只给数字与时间戳。这是 WIRED 三字体系统的中文等价物，也是与 R3.5（无衬线正文）最根本的区别。
2. **标题即 hero**：原报无配图，不造图。48px 衬线标题 + 20px 衬线导语撑起首屏。
3. **模块地图**：关键数字（P2 后，数据总览）→ 时间线（P7 后，编年视角）→ pull quote（P14 原位，真 pull-quote）→ 背景资料（P20 前，Note 式铺垫）。
4. **右 rail**：≥1200px 显示，锚点只有模块（关键数字/时间线/背景资料/文末），纯文字链 + scroll-spy。不发明叙事性小标题。
5. **颜色**：纸 #fdfbf8 / 墨三级 / 橙 / 红，全页无杂色（十六进制审计通过）。

## 砍掉的模块

**"主张与现实"对照模块——整个删除，零残留。**

核查过程：它的"主张"句（"胡塞武装的情况已经得到控制"）逐字出自正文 P5，"证据"句是 P2 机场袭击的复述。叙事本身在 P5 已经用"但"字完成了对照，独立模块只是把同一信息说第三遍，且把文章切碎。按 brief 规则（"如果 claim/evidence 让文章碎片化，就重做或删去"），删除是唯一正确的处理。静态检查确认无残留。

**保留的模块去重说明**：
- 关键数字：4 个 condensed 数据点（非正文复述），只出现一次
- 时间线：7 条单句 condensed，提供叙事顺序之外的编年视角
- 引语：Ulrichsen 那句**保留在 P14 正文流内**，视觉 breakout——标准编辑做法，不算重复
- 背景资料：context_cn 的 condensed 重述，放在 P20 前做铺垫

## 回应 R3.5 的七个问题

1. **像报告不像深读** → 单栏新闻流 + 衬线正文 + 编辑节奏，报告感来自卡片堆砌，本次零卡片
2. **正文没被治理** → 18px/1.9 衬线、640px 行宽、1.1em 段距、无 pretty，逐项治理
3. **组件多但节奏没变好** → 从 5 个模块砍到 4 个，位置按叙事弧线固定
4. **正文与模块重复** → 对照模块删除；引语流内化；其余 condensed 化
5. **移动端不稳** → 1440/768/390 三档 0 溢出，标题 32px/正文 17px，时间线不断轨
6. **字体系统不完整** → 三字体 + mono 范围 + 完整字号/行距/字重表（见简报）
7. **视觉判断分散** → 四色纪律 + 一套字体语言，结构和字体的判断收敛到同一套逻辑

## 验收六问（自答）

1. **首先像一篇能读下去的文章？** 是。24 段连续流，模块嵌入不打断叙事，没有卡片墙。
2. **正文比 R3.5 好读？** 客观指标达标（18px/1.9/640px）；主观等实读验证——衬线中文长文是本次最大胆的判断。
3. **模块减少无意义重复？** 是。对照模块已删；其余模块均为 condensed 视角或流内处理。
4. **AJ 结构 + WIRED 气质兼得？** 结构（masthead/新闻流/rail/模块纪律）是 AJ 的，字体（衬线三字体/标题hero/引语锚点）是 WIRED 的，同一套语言。
5. **手机真正可读？** 390px 0 溢出，17px 正文，模块堆叠正常，时间线不断轨。
6. **视觉语言统一？** 纸/墨/橙/红之外无杂色；结构判断与字体判断服从同一套纪律。

## v2 回炉记录（2026-10-13 09:36 批评 → 同日修复交付）

**批评**：v1 主次颠倒——视觉上过度 WIRED（48px/900 标题、18px 正文、26px 整段引语 breakout、大留白），AJ 只是"加入了 AJ 组件的 WIRED"。

**修复原则**：AJ 的尺度、密度、节奏 + WIRED 的字体家族。字体选择 ≠ 字号字重行高跟随。

| 元素 | v1（WIRED 尺度） | v2（AJ 尺度） |
|---|---|---|
| 标题 | 48px/900 | 40px/700（中文衬线大字重压迫感降级） |
| 导语 | 20px | 18px |
| 正文 | 18px/1.9 | 16px/1.8（AJ 密度） |
| 引语 | 整段 26px/700 breakout，上下发丝线 | 只取直接引语一句，20px/700 + 3px 黑左线 + 13px 署名行；叙述留在正文 |
| 关键数字 | 32px/900 | 28px/700，行距收紧 |
| 时间线正文 | 16px | 15px，条目间距 20→16px |
| 背景资料 | 15px | 14px |
| 模块边距 | 2.6em | 2em；首屏留白 56→40px |

**引语的人物/叙述/引语关系**：v1 把整段（含人物介绍和记者叙述）做成 breakout；v2 拆开——叙述留在正文流（普通 16px），只有直接引语进引语模块，署名行用 JSON 的 canonical 署名。这是 AJ 式的引用处理：适度强调，与正文协调。

**验收**：与 AJ 原型桌面/手机并排对比——一眼 AJ，字体是衬线；信息密度接近；无不必要的大字号/大粗体/大留白。结论："用 WIRED 字体的 Al Jazeera 阅读设计"成立。
